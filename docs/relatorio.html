1. Introdução

O presente trabalho tem como objetivo apresentar o desenvolvimento de um sistema automotivo para gestão de estoque de veículos, utilizando os conceitos de Programação Orientada a Objetos, persistência de dados e desenvolvimento de aplicações web com Java e Spring Boot.

O sistema foi desenvolvido para auxiliar concessionárias, vendedores e administradores no controle de veículos disponíveis em estoque. Por meio da aplicação, é possível cadastrar veículos, marcas e modelos, consultar informações, atualizar dados, excluir registros e aplicar filtros de pesquisa.

A proposta busca resolver um problema comum em empresas do setor automotivo: a dificuldade de manter informações organizadas, atualizadas e acessíveis sobre os veículos disponíveis para venda. Com o sistema, os dados ficam centralizados em um banco de dados MySQL e podem ser acessados por meio de uma API REST e de uma interface web simples.

2. Objetivo do Projeto

O objetivo principal do projeto é desenvolver um sistema CRUD orientado a objetos para gerenciamento de estoque de veículos.

Os objetivos específicos são:

  • Permitir o cadastro de veículos.
  • Permitir a consulta de veículos cadastrados.
  • Permitir a atualização de informações dos veículos.
  • Permitir a exclusão de veículos.
  • Permitir filtros por marca, modelo, ano, faixa de preço e status.
  • Permitir o cadastro de marcas.
  • Permitir o cadastro de modelos associados às marcas.
  • Utilizar banco de dados MySQL para persistência das informações.
  • Aplicar conceitos de Programação Orientada a Objetos.
  • Utilizar Java, Spring Boot, Spring Data JPA e Maven no desenvolvimento.

3. Descrição do Problema

Muitas concessionárias e lojas de veículos ainda enfrentam dificuldades para organizar seus estoques. Quando as informações são controladas manualmente, em planilhas ou em sistemas pouco integrados, podem ocorrer erros, perda de dados, atraso na atualização de informações e dificuldade para localizar veículos específicos.

Esses problemas afetam diretamente vendedores, clientes e gestores. Os vendedores podem perder tempo procurando informações sobre veículos disponíveis. Os clientes podem não encontrar rapidamente o modelo desejado. Já os gestores podem ter dificuldade para acompanhar o estoque, analisar disponibilidade e tomar decisões estratégicas.

Dessa forma, o sistema proposto busca centralizar as informações dos veículos em uma aplicação organizada, permitindo maior controle, agilidade e confiabilidade na gestão do estoque.

7. Entidades do Sistema

7.1 Veículo

A entidade Veículo representa os automóveis cadastrados no estoque da concessionária. Seus principais atributos são id, modelo, marca, ano, cor, preço, quilometragem e status.

7.2 Marca

A entidade Marca representa as fabricantes dos veículos, como Honda, Toyota, Chevrolet, Jeep e Volkswagen. Essa entidade ajuda a organizar os modelos e permite associar modelos à marca correta.

7.3 Modelo

A entidade Modelo representa o nome comercial do veículo, como Civic, Corolla, Onix, Compass ou Golf. Cada modelo pertence a uma marca.

8. Arquitetura do Sistema

O sistema foi organizado em camadas, seguindo boas práticas de desenvolvimento com Spring Boot. As principais camadas são Controller, Service, Repository, Entity, DTO, Exception e Config.

8.1 Controller

A camada controller é responsável por receber as requisições HTTP enviadas pelo usuário, navegador, Postman ou interface web.

8.2 Service

A camada service contém as regras de negócio da aplicação. Ela faz a ligação entre o controller e o repository.

8.3 Repository

A camada repository é responsável pela comunicação com o banco de dados. O projeto utiliza Spring Data JPA, que fornece métodos prontos para salvar, listar, buscar e excluir dados.

8.4 Entity

A camada entity contém as classes que representam as tabelas do banco de dados.

8.5 DTO

Os DTOs são usados para transportar dados entre a API e o cliente. Eles ajudam a separar os dados recebidos e devolvidos pela aplicação das entidades do banco.

8.6 Exception

A camada exception centraliza o tratamento de erros da aplicação, permitindo respostas padronizadas quando ocorre erro de validação, recurso não encontrado ou erro inesperado.

9. Fluxo da Aplicação

O funcionamento da aplicação segue o seguinte fluxo: o usuário acessa a interface web ou envia uma requisição pelo Postman; a requisição chega ao controller; o controller chama o service; o service aplica as regras de negócio; o repository acessa o banco de dados MySQL; o resultado é retornado ao usuário.

Fluxo resumido: Interface Web ou Postman → Controller → Service → Repository → MySQL.

10. Conceitos de Programação Orientada a Objetos Aplicados

10.1 Classes e objetos

As classes representam elementos do sistema, como Veiculo, Marca e Modelo. Cada veículo cadastrado no sistema é tratado como um objeto da classe Veiculo.

10.2 Atributos

Os atributos armazenam as características dos objetos. No caso da classe Veiculo, existem atributos como modelo, marca, ano, cor, preço, quilometragem e status.

10.3 Métodos

Os métodos representam comportamentos das classes. No projeto, as entidades possuem métodos para criação e atualização de dados.

10.4 Encapsulamento

O encapsulamento é aplicado por meio de atributos privados e métodos públicos de acesso. Isso protege os dados internos das classes e mantém maior controle sobre as alterações.

10.5 Enum

O enum StatusVeiculo define os valores permitidos para o status de um veículo, evitando que sejam cadastrados status inválidos. Os valores permitidos são DISPONIVEL, VENDIDO e RESERVADO.

10.6 Associação entre classes

A associação aparece na relação entre Modelo e Marca. Cada modelo pertence a uma marca, representando um relacionamento entre objetos.

10.7 Abstração

A abstração está presente principalmente nos repositories. O Spring Data JPA permite utilizar interfaces para acessar o banco sem escrever manualmente todos os comandos SQL.

10.8 Herança e interfaces

O projeto utiliza interfaces do Spring Data JPA, como JpaRepository. Os repositories herdam comportamentos prontos dessas interfaces, como salvar, buscar, listar e excluir registros.

11. Justificativa das Tecnologias Utilizadas

Java 21: foi escolhido por ser uma linguagem robusta, orientada a objetos e muito utilizada no mercado para desenvolvimento de sistemas corporativos.

HTML, CSS e JavaScript: foram utilizados para criar uma interface web simples, permitindo demonstrar o funcionamento do sistema de forma visual.

14. Interface Web

Além da API REST, o projeto possui uma interface web simples para demonstração das principais funcionalidades do sistema. Essa interface permite cadastrar, listar, editar, excluir e filtrar veículos de forma visual pelo navegador.

Para acessar a interface, primeiro é necessário que a aplicação esteja em execução. Portanto, o usuário deve abrir o projeto, configurar o banco MySQL e iniciar o Spring Boot pelo terminal com o comando:

mvn spring-boot:run

Após a aplicação iniciar corretamente, será exibida no terminal uma mensagem informando que o servidor Tomcat foi iniciado na porta 8080. Somente depois disso a interface poderá ser acessada pelo navegador.

Em ambiente local, normalmente o endereço utilizado é:

http://localhost:8080/

Esse endereço funciona quando o sistema está rodando no mesmo computador em que o navegador está sendo utilizado. Caso a aplicação esteja sendo executada em outro ambiente, como máquina virtual, servidor remoto ou ambiente em nuvem, será necessário acessar o endereço correspondente ao ambiente onde o projeto estiver rodando.

A API REST também pode ser acessada diretamente em formato JSON. Por exemplo, após iniciar a aplicação, a listagem de veículos pode ser consultada pelo endpoint:

/veiculos

Em ambiente local, o endereço completo costuma ser:

http://localhost:8080/veiculos

Dessa forma, a interface web é utilizada para facilitar a visualização do sistema, enquanto os endpoints da API permitem testar as funcionalidades também por ferramentas como Postman ou Insomnia.

15. Banco de Dados

O banco de dados utilizado é o MySQL. A aplicação utiliza JPA/Hibernate para criar e atualizar automaticamente as tabelas.

As principais tabelas são veiculos, marcas e modelos.

Relacionamento principal: Marca 1:N Modelo. Isso significa que uma marca pode possuir vários modelos, mas cada modelo pertence a uma única marca.

16. Testes e Validações

O sistema possui validações nos dados enviados pelo usuário. Campos obrigatórios, valores mínimos e formatos incorretos são tratados pela aplicação.

Exemplos de validações: modelo obrigatório, marca obrigatória, ano obrigatório, preço maior que zero, quilometragem não negativa e status obrigatório.

Também existe tratamento de erros para casos como veículo não encontrado, marca não encontrada, modelo não encontrado, JSON inválido e erro de validação.

17. Resultados Obtidos

Com o desenvolvimento do sistema, foi possível criar uma aplicação funcional para gestão de estoque de veículos. O sistema permite o cadastro completo de veículos, marcas e modelos, além de consultas, filtros, atualizações e exclusões.

A aplicação também demonstra a integração entre Java, Spring Boot e MySQL, aplicando conceitos de Programação Orientada a Objetos e organização em camadas.

18. Conclusão

O projeto desenvolvido atende ao objetivo proposto de criar um sistema automotivo para gestão de estoque de veículos. A aplicação permite controlar veículos cadastrados, organizar marcas e modelos, realizar filtros e manter os dados persistidos em banco MySQL.

Durante o desenvolvimento, foram aplicados conceitos importantes de Programação Orientada a Objetos, como classes, objetos, atributos, métodos, encapsulamento, enum, associação entre classes e uso de interfaces.

Além disso, o uso do Spring Boot facilitou a criação da API REST, enquanto o Spring Data JPA simplificou a integração com o banco de dados. A interface web simples contribui para demonstrar o funcionamento do sistema de forma visual.

Portanto, o sistema representa uma solução prática e organizada para o problema de controle de estoque de veículos em concessionárias.
